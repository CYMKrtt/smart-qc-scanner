# Smart QC Scanner — Prototype

ต้นแบบระบบตรวจสอบชิ้นงานด้วยกล้อง WebRTC บนสายพานการผลิต (Idea #1)
กล้องจับภาพ → ตรวจจับชิ้นงานในกรอบตรวจ → วิเคราะห์ตำหนิ → แจ้งเตือน/คัดออก → Dashboard แบบ Real-time

ไม่ต้องติดตั้ง package ใด ๆ ใช้แค่ **Node.js 18+**

## เริ่มใช้งาน

```bash
node server.js        # หรือดับเบิลคลิก start.bat
```

| หน้า | URL | ใช้ทำอะไร |
|---|---|---|
| หน้าแรก | http://localhost:8080 | ลิงก์ทั้งหมด + QR code สำหรับมือถือ |
| สถานีตรวจ | http://localhost:8080/station.html | คอมหน้าสายพาน: รับภาพ ตรวจ ตัดสิน PASS/FAIL |
| เดโมด่วน | http://localhost:8080/station.html?demo=1 | Simulator สายพาน + สอนต้นแบบอัตโนมัติ |
| กล้องมือถือ | https://&lt;IP เครื่อง&gt;:8443/camera.html | มือถือส่งภาพผ่าน WebRTC |
| Dashboard | http://localhost:8080/dashboard.html | สถิติ Real-time สำหรับหัวหน้างาน |

> มือถือเปิดกล้องได้เฉพาะบน **https** เซิร์ฟเวอร์จะสร้างใบรับรอง self-signed ให้อัตโนมัติ (ใช้ `openssl` ที่มากับ Git for Windows)
> ครั้งแรกบนมือถือจะมีคำเตือนความปลอดภัย ให้กด "ขั้นสูง → ดำเนินการต่อ" มือถือและคอมต้องอยู่ Wi-Fi เดียวกัน
> ถ้า IP เครื่องเปลี่ยน ให้ลบโฟลเดอร์ `certs/` แล้วรันใหม่

## ขั้นตอนการทำงาน

1. **เลือกแหล่งภาพ**: Simulator / Webcam ของเครื่อง / มือถือ (WebRTC)
2. **คาลิเบรตพื้นหลัง**: ให้กรอบตรวจว่าง ระบบจะจำภาพพื้นสายพาน (ทำอัตโนมัติ และกดซ้ำได้)
3. **สอนชิ้นงานต้นแบบ (Golden sample)**: ชิ้นงานดี 2–5 ชิ้น ระบบจะเรียนรู้ความแปรปรวนปกติจากต้นแบบหลายชิ้น
4. **ตรวจอัตโนมัติ**: ทุกชิ้นที่ผ่านกรอบจะถูกตรวจ 1 ครั้ง ทั้งบนสายพานที่เคลื่อนที่ และการวางชิ้นงานนิ่ง ๆ

### สิ่งที่ตรวจได้ (โหมด Golden sample, ทำงาน offline)
| ตรวจ | วิธี |
|---|---|
| ขนาดผิดสเปก | เทียบพื้นที่ silhouette กับต้นแบบ |
| รูปร่างผิด / ชิ้นส่วนขาด | เทียบ silhouette แบบ normalize (รองรับชิ้นงานหมุน 90°/180°) |
| ตำหนิผิว / รอยขีดข่วน / คราบ | เทียบลวดลายความสว่าง + สี ทีละพิกเซล (ทนต่อการเลื่อนเล็กน้อยและแสงเปลี่ยน) |
| สีผิดเพี้ยน | เทียบ chromaticity เฉลี่ย |

ผลแต่ละชิ้นมี heat-map จุดตำหนิ (แดง = ผิว, ส้ม = รูปร่าง) และแถบคะแนนเทียบเกณฑ์

### โหมด AI (สอนเอง)
MobileNet + KNN (TensorFlow.js โหลดจาก CDN ครั้งแรก ต้องใช้อินเทอร์เน็ต) กด “ชิ้นล่าสุด = ดี/เสีย” เพื่อสอน
หรือเปิด “สอนอัตโนมัติจากเฉลย Simulator” แล้วเลือกโหมด **AI** หรือ **Hybrid** (ไม่ผ่านถ้าวิธีใดวิธีหนึ่งพบตำหนิ)

### แจ้งเตือน / คัดแยก
- สถานี: กรอบแดง + เสียงเตือน, มือถือที่เป็นกล้องจะกระพริบแดงและสั่น
- Dashboard: แจ้งเตือนมุมจอ
- ต่อ PLC / ตัวคัดแยก: ตั้ง `REJECT_WEBHOOK` แล้วเซิร์ฟเวอร์จะ POST JSON ทุกครั้งที่พบของเสีย
  ```bash
  set REJECT_WEBHOOK=http://192.168.1.50/reject && node server.js
  ```

## ขึ้นเว็บจริงด้วย Render (ง่ายสุด ไม่ต้องเปิดคอมทิ้งไว้)

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/CYMKrtt/smart-qc-scanner)

1. กดปุ่มด้านบน → ล็อกอินด้วย GitHub
2. ช่อง `ACCESS_PASSWORD` ใส่รหัสผ่านที่จะให้เพื่อนใช้ → กด Deploy
3. รอ 2–3 นาที จะได้ลิงก์ `https://smart-qc-scanner-xxxx.onrender.com` ส่งลิงก์ + รหัสให้เพื่อน (ช่องชื่อผู้ใช้กรอกอะไรก็ได้)

- แบบฟรี: ไม่มีคนเข้า 15 นาทีเซิร์ฟเวอร์จะหลับ คนแรกที่เข้าต้องรอ ~1 นาที
- ผลตรวจและรูปจะหายเมื่อเซิร์ฟเวอร์รีสตาร์ท (เหมาะกับเดโม ถ้าจะเก็บข้อมูลจริงให้รันบนเครื่องตัวเอง)
- push โค้ดใหม่ขึ้น GitHub แล้ว Render จะอัปเดตเว็บให้อัตโนมัติ

## ให้เพื่อนเข้าใช้ผ่านอินเทอร์เน็ต (รันบนเครื่องตัวเอง)

> ต้องตั้งรหัสผ่านก่อนเสมอ ไม่งั้นใครได้ลิงก์ก็กด "ล้างข้อมูล" ได้

ใช้ **ngrok** (ฟรี) — ห้ามใช้ Cloudflare Quick Tunnel (`trycloudflare.com`) เพราะไม่รองรับ SSE ทำให้ Dashboard ไม่อัปเดตและกล้องมือถือเชื่อมต่อไม่ได้

1. ติดตั้งและตั้งค่า (ครั้งเดียว)
   - `winget install Ngrok.Ngrok` แล้ว `ngrok update`
   - สมัครฟรีที่ https://dashboard.ngrok.com/signup แล้วคัดลอก authtoken
   - `ngrok config add-authtoken <TOKEN>`
2. รันเซิร์ฟเวอร์พร้อมรหัสผ่าน
   ```bash
   set ACCESS_PASSWORD=รหัสของคุณ && node server.js
   ```
3. เปิดอีกหน้าต่างแล้วรัน
   ```bash
   ngrok http 8080
   ```
   จะได้ลิงก์ `https://xxxx.ngrok-free.app` ส่งลิงก์ + รหัสผ่านให้เพื่อน (ช่องชื่อผู้ใช้กรอกอะไรก็ได้)

- ครั้งแรกเพื่อนจะเจอหน้าเตือนของ ngrok ให้กด "Visit Site"
- ใช้ได้เฉพาะตอนที่เครื่องนี้เปิดและรันทั้ง 2 คำสั่งอยู่
- ลิงก์เป็น https จริง มือถือเปิดกล้องได้เลยโดยไม่มีคำเตือน
- ส่งภาพกล้องข้ามเครือข่ายคนละที่ (WebRTC) อาจต่อไม่ติดในบางเครือข่าย เพราะใช้แค่ STUN ไม่มี TURN server

## ผลทดสอบกับ Simulator

สายพาน 420 px/s, ของเสีย 50% (สุ่ม 6 แบบ), ชิ้นงานกลับหัว 180° แบบสุ่ม, แสงกระพริบ ±3%, สอนต้นแบบ 2 ชิ้น:

| | จำนวน | ถูกต้อง |
|---|---|---|
| ของดี | 63 | 63 (ไม่มีการคัดของดีทิ้ง) |
| สีเพี้ยน / ขนาดเล็ก / ไม่มีลายพิมพ์ / มุมบิ่น / คราบ | 65 | 65 |
| รอยขีดข่วน | 17 | 13 |
| **รวม** | **145** | **97.2%** · ~120 ms/ชิ้น |

ชิ้นที่หลุดคือรอยขีดข่วนบาง ๆ ที่พาดบนลายพิมพ์สีเข้ม ซึ่งแทบไม่มี contrast
**ตัวเลขนี้มาจาก Simulator** ซึ่งเป็นภาพสังเคราะห์ที่สะอาด ถ้าเป็นกล้องจริงต้องวัดใหม่กับชิ้นงานจริง
(ใช้คอลัมน์ `truth` ใน CSV ได้ถ้าติดเฉลยเอง)

## เคล็ดลับเมื่อใช้กับชิ้นงานจริง
- กล้องตั้งฉากกับสายพาน ระยะคงที่ พื้นสีเรียบที่ตัดกับชิ้นงาน
- แสงคงที่และสม่ำเสมอ ตามที่ผู้ใช้ให้ feedback ไว้ (ไฟแฟลชมือถือ/ไฟ LED ช่วยได้มาก) แสงเปลี่ยนมากให้คาลิเบรตใหม่
- สอนต้นแบบ 3–5 ชิ้น เพื่อให้ระบบตั้งเกณฑ์จาก noise จริงของกล้อง
- คัดของดีทิ้งบ่อย → ลด “ความไว”, ของเสียหลุด → เพิ่ม “ความไว”
- เปิด “แสดง mask” เพื่อดูว่าระบบแยกชิ้นงานจากพื้นได้ดีแค่ไหน (ปรับ “เกณฑ์แยกชิ้นงานจากพื้น”)
- ข้อจำกัด: ชิ้นงานที่หมุนเอียงมาก (ไม่ใช่ 0/90/180/270°) จะถูกมองว่าผิดรูป ควรมีรางบังคับทิศทาง

## โครงสร้าง
```
server.js              HTTP/HTTPS, WebRTC signaling (SSE), API เก็บผล + รูป, webhook
public/station.html    สถานีตรวจ          public/js/station.js
public/camera.html     กล้องมือถือ WebRTC   public/js/camera.js
public/dashboard.html  Dashboard          public/js/dashboard.js
public/js/vision.js    ตรวจจับ/ติดตามชิ้นงาน + เทียบต้นแบบ (หัวใจของระบบ)
public/js/simulator.js สายพานจำลองพร้อมเฉลย
public/js/ai.js        MobileNet + KNN
data/                  inspections.jsonl + รูปภาพ (สร้างอัตโนมัติ)
```

API: `GET /api/inspections`, `GET /api/stats`, `GET /api/export.csv`, `GET /api/stream` (SSE), `POST /api/reset`
